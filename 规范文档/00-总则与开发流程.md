## 1. 总则

1. **规范先行**：未写入本目录的产品行为，实现阶段不得「先写再说」。  
2. **单一事实源**：产品/工程约束以 `规范文档/` 为准；代码与评测是规范的落地与证据。  
3. **垂直场景锁定**：企业内部制度知识库问答（报销 / 考勤 / IT 等）；非目标见 [01](01-场景与价值.md)。  
4. **可证明**：改动必须能被评测或 Trace 复现；禁止只凭体感优化（见 [03](03-评测规范.md)、[04](04-优化手册.md)）。  
5. **轻量默认**：SQLite + hybrid + Mock；向量/图谱默认可关（见 [06](06-架构分层与迭代计划.md)）。

## 2. Cursor 模式怎么用

| 阶段 | 模式 | 做什么 |
|------|------|--------|
| 改规范口径、排期、方案权衡 | **Plan** | 对齐验收，避免直接堆功能 |
| 按 [07](07-现状差距与实现待办.md) 改代码 / 扩评测 | **Agent** | 严格对照规范落实现 |
| 只读问「这段代码干什么」 | **Ask** | 不改文件 |
| 评测红了 / 行为异常 | **Debug** 或 Agent + Trace | 对照 `run_id` / spans |

原则：**Plan 锁口径 → Agent 薄实现 → 评测证明 → 再优化**。

## 3. 开发流程（T0–T6）

```text
T0 规范成套（本目录）✅
 → T1 场景金标准进 cases.yaml + demo ✅
 → T2 链路加固（制度禁 web 编造；空库拒绝进评测）✅
 → T3 题库 ~50 + 基线归档 ✅（后续增强至 **100**）
 → T4 按 04 做 1～2 个优化并用评测证明 ✅
 → T5 Prompt 版本 / Trace 字段 / 工程项 ✅
 → T6 向量/图谱仅在评测证明召回不足后开启 ⏸（有意不做：召回已够用）
```

### 每轮退出标准（DoD）

- [01](01-场景与价值.md) 四问仍成立，非目标未漂移  
- `python scripts/run_eval.py` 不回退  
- `GET /api/runs` 能复现 intent / 检索 / 工具 spans  
- 若有优化：在 [04](04-优化手册.md) 证据账本记一条  

### 关键命令

```powershell
python scripts/run_eval.py
python scripts/demo_scenarios.py
```
