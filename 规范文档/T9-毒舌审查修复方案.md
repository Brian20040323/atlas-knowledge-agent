## Bug #3+#5 · answer-section 渲染重构

### 根因
在已渲染的 HTML 上做正则匹配——两层错误：
1. 依赖 renderMarkdown 输出格式不变（不保证）
2. section div 不闭合

### 正确方案：文本阶段切分，分段渲染

```javascript
function renderAnswerSections(rawText) {
  const sections = [];
  const markers = [
    { key: "**制度依据**", cls: "as-policy",  icon: "📋" },
    { key: "**推理分析**", cls: "as-reasoning", icon: "💭" },
    { key: "**结论**",     cls: "as-conclusion", icon: "✅" },
    { key: "**补充说明**", cls: "as-note",  icon: "⚠️" },
  ];

  // 找所有 marker 位置
  let positions = [];
  for (const m of markers) {
    let idx = rawText.indexOf(m.key);
    if (idx >= 0) positions.push({ idx, ...m });
  }
  if (!positions.length) return renderMarkdown(rawText);

  // 按位置排序
  positions.sort((a, b) => a.idx - b.idx);
  
  // 第一段之前的内容
  if (positions[0].idx > 0) {
    sections.push(renderMarkdown(rawText.slice(0, positions[0].idx).trim()));
  }

  // 每个 section
  for (let i = 0; i < positions.length; i++) {
    const p = positions[i];
    const contentStart = p.idx + p.key.length;
    const contentEnd = i + 1 < positions.length ? positions[i + 1].idx : rawText.length;
    const body = rawText.slice(contentStart, contentEnd).trim();
    const bodyHtml = renderMarkdown(body);
    sections.push(
      `<div class="answer-section ${p.cls}">
        <div class="as-head">
          <span class="as-badge">${p.icon}</span>${p.key.replace(/\*\*/g, "")}
        </div>
        <div class="as-body">${bodyHtml}</div>
      </div>`
    );
  }

  return sections.join("");
}
```

### 关键差异

| 旧方案 | 新方案 |
|--------|--------|
| 在 HTML 上正则匹配 | 在纯文本上找 marker |
| section div 不闭合 | 每个 section 完整闭合 |
| 依赖 renderMarkdown 格式 | 文本阶段就确定了边界 |

### 验收
- v3 四段式回答 → 四个独立闭合的 section div
- 旧格式回答（无 marker）→ 正常渲染，无 section

## Bug #8 · composite 绕过管道

### 问题
`_handle_composite` 独立创建 LLM 请求，不共享熔断/缓存/降级/thinking。

### 方案：轻量替代——不接入全管道

接入全管道成本太高（需要重构 composite 为多个 plan_turn 调用）。替代方案：

1. **composite 不独立调 LLM**：改为对每个子查询单独走 `stream_chat`（复用管道）
2. **并行调用**：`asyncio.gather` 对每个子查询发起独立 `stream_chat`
3. **合并结果**：收集所有子回答，按分节标题拼接

```python
# 简化方案：composite → 多个独立 stream_chat
async def _handle_composite_v2(self, messages, plan, trace, ...):
    sub_queries = plan.sub_queries or []
    
    async def chat_one(sq):
        sub_msgs = list(messages[:-1]) + [{"role": "user", "content": sq}]
        buf = ""
        async for event in self.stream_chat(sub_msgs, use_tools=False, deep_think=False):
            if event.get("type") == "token":
                buf += event.get("content") or ""
        return sq, buf.strip()
    
    results = await asyncio.gather(*[chat_one(sq) for sq in sub_queries])
    
    # 拼接
    sections = []
    for sq, answer in results:
        sections.append(f"### {sq}\n{answer or '暂无结果'}")
    yield from self._emit_text("\n\n".join(sections))
```

### 注意
这个方案复用了 `stream_chat` 的全部管道（检索→熔断→缓存→降级），但增加了 N 次 LLM 调用。在 Mock 模式下不会有额外开销。
