# 05 · 工程化规范

> 原则：**不要一上来做很重**，但要有配置、日志、异常、Prompt 版本、测试集与 Trace，使得问题可排查、效果可复现、优化可证明。  
> 版本：v1.0 · 2026-07-16

---

## 1. 轻量基线（默认路径）

| 项 | 默认 | 说明 |
|----|------|------|
| 存储 | SQLite `data/app.db` | 无强制 Postgres |
| 检索 | lexical + TF-IDF hybrid | 向量默认关 |
| 图谱 | 默认关 | 失败不影响文档 RAG |
| LLM | `MOCK_MODE=auto` | 无 Key 可演示 |
| 语音 | 懒加载可关 | 防拖垮本机 |

重模块（向量 / 图谱 / Whisper / XTTS）必须：**可关、有上限、失败可降级**。详见母本第 7–8 章。

---

## 2. 配置管理

| 要求 | 落地 |
|------|------|
| 单一配置源 | `backend/app/config.py` + `.env` |
| 示例可复制 | `.env.example` 与真实键名一致 |
| 密钥不进库 | `LLM_API_KEY` 等仅环境变量；禁止提交 `.env` |
| 行为可开关 | `MOCK_MODE`、`RAG_VECTOR_ENABLED`、`RAG_GRAPH_ENABLED`、超时与并发上限 |

变更配置后：更新 `.env.example` 注释 + 相关规范一句说明。

---

## 3. 日志与异常处理

### 3.1 用户可见 vs 内部

| 场景 | 用户可见 | 内部 |
|------|----------|------|
| 校验失败（上传超限等） | 4xx + 可读原因 | 校验日志 |
| 并发过多 | 429 稍后重试 | concurrency 计数 |
| LLM 失败 | 降级 Mock 作答（若有 hits） | `llm_error` span |
| 外网失败 | 跳过联网，尽量本地答 | `circuit_*` / tool error |
| 空库 | 明确暂无依据 | `hits=0` |
| 未捕获异常 | 通用错误提示，不裸堆栈给前端 | 服务端完整日志 |

### 3.2 超时与重试

- 外部 HTTP **必须有超时**（母本：web / research / LLM 分项配置）  
- 写库与自动入库 **默认不盲目重试**（防重复文档）  
- 熔断：连续外网失败达阈值后本轮跳过

## 4. Prompt 版本管理

### 4.1 最低标准（T5 前可先约定）

1. 所有系统提示 / 综合提示旁标注版本号，例如：

```text
PROMPT_VERSION = "policy_synth_v1"
```

2. 变更时：版本号 +1，并更新 [08-Prompt版本与变更记录.md](08-Prompt版本与变更记录.md)：

| 版本 | 日期 | 变更 | 关联评测 |
|------|------|------|----------|
| policy_synth_v1 | 2026-07-16 | 初版：要求 **参考** 与拒空库 | citation_refs / empty_result |

3. **禁止**只改线上字符串不改版本号。

### 4.2 与评测挂钩

Prompt 变更视为行为变更：必须跑 `run_eval.py`，基线表记一笔。

## 5. 可观测性（Trace）

**实现**：`backend/app/observability/traces.py` → `AgentTrace`  
**查询**：`GET /api/runs`

### 5.1 每轮至少记录

| 字段 | 用途 |
|------|------|
| `run_id` | 关联前后端与排障 |
| `query` | 复现输入（注意长度截断） |
| `intent` | 路由是否正确 |
| `mode` | mock / llm / mock_fallback |
| `hit_count` | 检索是否空 |
| `duration_ms` | 性能 |
| `spans[]` | 分段耗时与错误 |

### 5.2 关键 span（排障常用）

| span | 看什么 |
|------|--------|
| `retrieve_local` / `retrieve_score` | 是否检索、backend、hits |
| `plan` | 意图与计划 |
| `tool_*` | 工具成败与次数 |
| `circuit_skip` | 是否熔断跳过外网 |
| `llm_synthesize` / `llm_fallback_mock` | 综合路径 |
| `graph_*` | 图谱是否介入 |

### 5.3 理想增强（不阻塞 MVP）

在 spans.meta 或旁路日志中沉淀：

- 检索 query（含 rewrite 后）  
- Top-K 标题列表  
- 模型输入/输出摘要（注意脱敏与长度）  
- 工具参数与返回摘要  

有了这些，才能「排除问题、复现效果、证明优化不是凭感觉」。

## 6. 测试集沉淀

| 规则 | 说明 |
|------|------|
| 唯一门禁源 | `backend/tests/eval/cases.yaml` |
| 禁止静默删 case | 失败先修；暂不可测标 skip+原因 |
| 种子数据可重复 | 评测前置入库步骤脚本化或文档化 |
| 基线归档 | `规范文档/eval-baselines/`（见 03） |
| CI | `.github/workflows/eval.yml` 全绿才合并 |

分类与指标定义见 [03-评测规范.md](03-评测规范.md)。

## 7. 目录与职责（防腐）

与母本分层一致：

| 层 | 目录 | 禁止 |
|----|------|------|
| 表现 | `frontend/`、`api/` | 写打分逻辑 |
| 应用 | `agents/`、`tools/` | 直接散落 SQL 细节 |
| 领域 | `rag/` | 依赖 SSE/前端 |
| 基础设施 | `db/`、`observability/`、`mcp/` | 承载「该不该联网」等业务决策 |

新增检索后端：实现统一接口 + 配置开关，而不是在路由里堆 `if`。
