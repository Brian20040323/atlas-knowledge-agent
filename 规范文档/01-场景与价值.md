# 01 · 场景与价值

> 垂直主叙事：企业内部制度知识库问答  
> 实现对照：Atlas（本仓库）  
> 版本：v1.0 · 2026-07-16

---

## 1. 四问（评审必须能答清）

| 问题 | 本项目的答案 |
|------|----------------|
| **谁在用？** | ① 员工：自助查报销 / 考勤 / IT 支持制度；② HR / 行政：维护制度文档并保证口径一致；③ 新员工：onboarding 时快速理解公司规则 |
| **在什么场景用？** | 差旅报销能不能报、额度多少、要哪些附件；请假规则；账号权限流程等「必须有制度依据」的问答 |
| **原来有什么痛点？** | 翻企微群 / 找 PDF；口头口径不一致；通用大模型会编造制度；HR 重复答同类问题；演示时无 Key 或外网挂了就断 |
| **Agent 解决了什么？** | 先检索制度再带依据作答；库内无依据时**明确拒绝**而非编造；回答可追溯到 `document_id`；失败可降级，链路可 Trace |

一句话产品定位：

> 面向企业内部制度的「**可引用、可拒绝、可降级**」问答 Agent：有依据才答，无依据不装懂。

## 2. 垂直场景边界

### 2.1 在范围内

- 已入库制度文档的问答（报销、考勤、假期、IT 支持流程等）
- 制度文档的入库 / 更新（学习、上传 PDF/MD）
- 多轮追问同一制度细节（额度、附件、审批人）
- 知识缺失与超范围时的明确拒绝

### 2.2 非目标（明确不做）

- 企业级多租户、细粒度 ACL、合规审计平台
- 替代财务系统自动发起报销单
- 全网搜索「别的公司怎么报销」并当作本公司制度
- 无依据时由模型「合理推测」制度条款

### 2.3 制度场景硬约束

| 约束 | 说明 |
|------|------|
| 禁止自由发挥 | 制度类问题不得仅靠模型参数记忆作答 |
| 禁止空库编造 | 检索无命中 → 明确「库内暂无依据」，可提示补充文档 |
| 禁止制度问题自动联网编答案 | 外网结果**不能**当作本公司制度；除非用户显式「联网：…」且答案标注「非本公司制度」 |
| 必须可追溯 | 有断言的硬规则（额度、比例、天数）须能对应到文档标题或 `document_id` |

## 3. 可验收场景表

每个场景：**输入 → 系统行为 → 成功标准 → 失败表现**。

### S1：制度命中（金标准）

| 项 | 内容 |
|----|------|
| 输入 | 「差旅报销住宿费上限是多少？」（库内已有《差旅报销制度》） |
| 系统行为 | 意图 → 本地检索 → 命中制度块 → 带引用综合作答 |
| 成功标准 | 回答含制度中的关键数字/条款；含 `**参考**` 且可追溯 `document_id`；评测 `must_hit_title_any` 通过 |
| 失败表现 | 答非所问；有数字但无引用；引用了无关文档 |

### S2：知识缺失 → 明确拒绝

| 项 | 内容 |
|----|------|
| 输入 | 「我们公司海外医疗险报销比例是多少？」（库内无相关文档） |
| 系统行为 | 检索空或弱相关 → **拒绝断言**，提示入库 / 联系 HR |
| 成功标准 | 回答含「不足以 / 暂无依据」类表述；**禁止**编造比例数字；`forbid` 虚假肯定句 |
| 失败表现 | 编造「一般是 80%」等看似真实的答案 |

### S3：超范围拒绝

| 项 | 内容 |
|----|------|
| 输入 | 「帮我写一首诗」或「今天股市怎么样？」（非制度场景且未显式联网） |
| 系统行为 | 识别为超范围或非 LOCAL 制度问答 → 拒绝或引导到正确入口 |
| 成功标准 | 不假装用制度库回答；不输出伪造的制度条款 |
| 失败表现 | 用知识库噪声片段硬凑无关答案 |

### S4：制度入库后可查

| 项 | 内容 |
|----|------|
| 输入 | `记住：差旅报销制度\|住宿费上限 500 元/晚…` 或上传制度 PDF |
| 系统行为 | 解析入库 → 写入 `documents` → 确认反馈 |
| 成功标准 | 再次提问 S1 可命中；内容持久化于 SQLite |
| 失败表现 | 入库成功但检索打不到；超限文件未返回可读错误 |

### S5：多轮追问不丢主题

| 项 | 内容 |
|----|------|
| 输入 | 「报销住宿上限？」→「那机票呢？」→「需要什么附件？」 |
| 系统行为 | 保持「差旅报销」上下文（历史摘要或槽位）→ 分别检索相关条款 |
| 成功标准 | 后两轮仍围绕差旅制度，不漂移到无关文档 |
| 失败表现 | 「机票呢」被当成空查询或答成其他制度 |

## 4. 人群 × 价值矩阵

| 人群 | 核心诉求 | Agent 交付 |
|------|----------|------------|
| 员工 | 快速、准确、有出处 | 秒级检索 + 引用 + 不确定时拒绝 |
| HR / 行政 | 口径统一、少重复答疑 | 单一知识源；更新文档即更新答案 |
| 评审 / 面试官 | 看清场景与工程闭环 | 四问清晰 + 链路 + 评测 + 优化证据 |
| 开发者（Atlas） | 本地可演示、可扩展 | Mock 全链路；Trace；`cases.yaml` 门禁 |

## 5. Atlas 实现对照

本仓库当前定位是「可学习 Agent 知识库脚手架」；**评审叙事用企业制度问答**，演示时用同一套链路：

| 制度叙事 | Atlas 能力 |
|----------|------------|
| 制度入库 | `记住：标题\|内容` / 上传 / `learn_knowledge` |
| 制度问答 | 预检索 `retrieve_local` → `plan_turn` → synthesize + `**参考**` |
| 无依据拒绝 | 空 hits 话术（评测 `empty_result_answer`） |
| 可观测 | `AgentTrace` / `GET /api/runs` |
| 回归 | `backend/tests/eval/cases.yaml` + `scripts/run_eval.py` |

演示话术建议：先入库一篇《差旅报销制度》样例，再走 S1 / S2，并打开 Trace 展示「先检索后作答」。
