# 10 · 运行验收与降级清单

> 用途：发布前或检索链路调整后，按真实 Atlas 架构执行 API 冒烟、降级和压测验收。  
> 版本：v1.0 · 2026-07-23

## 1. 架构口径

- Planner：规则式 `backend/app/agents/planner.py::plan_turn`，不是 `LLMPlanner` 单例。
- Dense：`backend/app/rag/embeddings.py` 提供 hash / FastEmbed / OpenAI-compatible embedding。
- 向量后端：`backend/app/rag/vector_index.py` 本地索引，不依赖 Qdrant。
- 混合检索：`backend/app/rag/retriever.py` 使用 weighted dense + lexical/TF-IDF，不宣称 RRF。
- 重建入口：`POST /api/knowledge/reindex`，受 `RAG_VECTOR_ENABLED` 和当前用户知识库范围约束。

禁止为了匹配外部方案而新建 `llm_planner.py`、`dense.py`、`vector_store.py`，或删除仍被 `vector_index.py` 引用的 `embeddings.py`。

## 2. 启动前

- [ ] 安装 `backend/requirements.txt`。
- [ ] `data/` 可写。
- [ ] 真实模型配置 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`；无 Key 时确认允许 mock。
- [ ] 明确 `ATLAS_USER_AUTH`：开启时，知识库与 chat 验收必须使用登录 Cookie。
- [ ] 如配置 `ATLAS_REGISTER_SECRET`，自测注册时设置 `ATLAS_SELFTEST_INVITE_CODE`。

## 3. 启动与 API 冒烟

启动：

```powershell
python run.py
```

检查：

- [ ] `GET /api/health` 返回 `status=ok`。
- [ ] `GET /api/auth/me` 的 `auth_required` 与当前配置一致。
- [ ] `GET /api/knowledge/retrieval-meta`：
  - 向量开启：`retrieval=dense+sparse-hybrid`、`fusion=weighted-dense+lexical`、`vector_backend=local-vector-index`。
  - 向量关闭：`retrieval=sparse-tfidf-hybrid`。
- [ ] `POST /api/knowledge/reindex`：
  - 向量开启：`ok=true`，并返回当前用户范围内的文档数。
  - 向量关闭：`ok=false`、`reason=rag_vector_enabled=false`，这是预期降级。
- [ ] `POST /api/chat` 能按 SSE 返回 `plan / thinking / token / tool / done` 中适用的事件，并最终出现 `done`。

## 4. 制度导入回归

服务处于真实 LLM 模式时执行：

```powershell
.\.venv\Scripts\python.exe scripts\selftest_policy_import.py
```

若默认 8000 端口被其他进程占用，可对隔离服务指定地址：

```powershell
$env:ATLAS_SELFTEST_BASE_URL="http://127.0.0.1:8001"
.\.venv\Scripts\python.exe scripts\selftest_policy_import.py
```

- [ ] L0 health：`mode=llm`。
- [ ] L1 上传成功。
- [ ] L2 原文关键点完整。
- [ ] L3 文档列表可见。
- [ ] L4 检索命中目标制度。
- [ ] L5 问答无硬失败；已知旧文档/FAQ 抢答可单列 soft-fail，不可掩盖 L1–L4 失败。

结果文件：`data/_selftest_policy_result.json`。

## 5. 降级测试

在隔离测试进程中设置 `RAG_VECTOR_ENABLED=false` 后重启，不修改生产配置：

- [ ] `/api/knowledge/search` 仍可通过 lexical/TF-IDF 返回结果。
- [ ] `/api/knowledge/retrieval-meta` 返回 `sparse-tfidf-hybrid`。
- [ ] 不卸载不存在的 `qdrant-client`；FastEmbed 不可用时应降级到 hash provider。

## 6. 评测与压测

行为变更后执行：

```powershell
.\.venv\Scripts\python.exe scripts\run_eval.py
```

压测命令与历史基线见 [`../docs/LOAD_TEST.md`](../docs/LOAD_TEST.md)。验收要求：

- [ ] 常规查询与冷查询 Failure Count 均为 0。
- [ ] 两条检索路径 P95 均低于 2000ms。
- [ ] QPS/P95 等对外数字仅引用本次可复现报告。

## 7. 失败定位

- `ImportError`：先核对 requirements 和虚拟环境，不要临时引入 Qdrant。
- reindex 返回 `ok=false`：先确认向量开关。
- 401：确认账号隔离与 Cookie，不要把鉴权失败误判为检索失败。
- 本地索引异常：优先调用 reindex；必要时备份后清理 `data/vector_index/` 再重建。
- 评测回退：先沉淀 bad case，再调整检索权重或路由；不以更换向量数据库作为默认修复。
