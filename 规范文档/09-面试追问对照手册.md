## 追问深度展开

### Q1 · 多轮记忆 — 不是「把历史塞进 prompt」

面试官可能会问：「你不是简单地把前几轮对话放进 prompt 吧？」

你的回答：
> 不是。我们用了两种机制：(1) **槽位** — `dialogue_slots.py` 维护轻量上下文槽位（`policy_name`、`topic`、`last_query`），从 assistant 回答中提取主题词；(2) **改写** — `build_search_query()` 把「那薪资呢」补全为「员工制度 薪资」后再检索。槽位更新无 LLM 开销，0 延迟。提示词只传最近 6 轮消息，不传全文历史。

### Q2 · 检索策略 — 为什么不用向量？

面试官可能会追问：「向量检索不是更好吗，你凭什么不用？」

你的回答：
> 向量检索（P3）代码已完成，但默认关闭。原因有二：(1) 证据驱动 — 当前 126 道评测全绿，词法召回已经足够，启用向量反而可能因为 embedding 噪声导致 bad case 回归；(2) 零依赖 — 词法不需要 GPU 或 embedding API，答辩时可以直接演示。P3 的接口保留了 `retriever.py:retrieve_vector_hybrid`，真正需要时打开配置即可，无需改代码。

### Q3 · Rerank 缺失 — 为什么没有专用重排模型？

> 我们对 rerank 的理解是「去噪」而非「改序」。`filter_relevant_hits` 干了这件事：低分命中直接丢弃，不进入综合层。对于制度类短文本（单篇文档 200-500 字），词法打分已经足够区分相关和无关。专用 reranker 的价值主要在于长文本、多来源混合检索场景，目前不是瓶颈。

### Q4 · 检索差怎么办 — 三层降级的具体触发条件

| 条件 | 行为 | 用户感知 |
|------|------|---------|
| hits 存在但均低分（score<阈值） | `filter_relevant_hits` 返回空 → 进入"无命中"逻辑 | 看是否触发下面两条 |
| 无命中 + 非制度问题 | `needs_external_research` → 自动 research/web | 等待略长，但能拿到结果 |
| 无命中 + 是制度问题 | `policy_refuse=True` → 直接拒答 | 明确告知缺什么 |

### Q8 · 空库拒答 — 不只是「不知道」

面试官可能会问：「拒答一句话就完了？用户不知道该怎么办怎么办？」

> 我们的拒答包括三个部分：(1) 承认不足「目前掌握的材料还不足以回答」；(2) 给出原因「缺乏相关制度文档」；(3) 给出路径「您可以上传制度文件，或使用『记住：标题|内容』写入后重试」。拒绝是「负责任的不回答」，不是「我不知道」。

### Q9 · LLM 挂了 — mock_fallback 的完整链路

```
用户提问 → 检索本地知识（正常执行）
         → 调用真实 LLM（超时/5xx）
         → 捕获异常标记 llm_failed=True
         → 改用 synthesize_knowledge_answer() + 已检索素材
         → 生成结构化回答（含引用）
         → Trace 标记 mode=mock_fallback，span 含 llm_error
```

> 关键：检索环节不受影响，所以即使 LLM 挂了，用户仍能看到基于本地知识的回答。不是纯 mock 编造，而是用真实检索结果做规则综合。

## 能力边界自查

| 你的系统能做什么 | 你的系统明确不做什么 |
|-----------------|---------------------|
| 检索已入库制度文档并引用回答 | 推测未入库的制度条款 |
| 识别口语别名（宾馆→住宿、房费→住宿费） | 处理完全未覆盖的别名（无向量） |
| 多轮上下文追踪（槽位改写） | 无限历史窗口（只保留最近 6 轮） |
| 自主学习 + 联网补充（非制度） | 自动联网当做制度答案 |
| 并发 4 以内 | 高并发场景 |
| 单文档 ≤200k 字符 | 超大文档分库 |
| 空库拒答 + 提示补充路径 | 空库猜测 |
