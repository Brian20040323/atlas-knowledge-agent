# 04 · 优化手册

> 含金量不在「搭过一个系统」，而在：**发现了什么问题 → 如何改 → 用评测证明变好了**。  
> 版本：v1.0 · 2026-07-16

---

## 1. 优化纪律

1. **先基线后动手**：记下 `run_eval` 通过率与相关分类指标（见 [03-评测规范.md](03-评测规范.md)）。  
2. **一次只改一类根因**：例如本周只做 query rewrite，不顺手改五个开关。  
3. **必须有对照**：改前 / 改后同一题库、同一种子数据。  
4. **写入本手册「证据账本」**：禁止只说「感觉流畅多了」。  
5. **不回退门禁**：整体 `passed/total` 不得下降；若换题库需在基线注明。

## 2. 症状 → 根因 → 改法 → 评测

### 2.1 检索不准（该命中的制度打不到）

| 项 | 内容 |
|----|------|
| 症状 | 用户问「住宿标准」，库有《差旅报销制度》却命中无关文档或空 |
| 根因假设 | 查询词与文档用词不一致；分块切坏；lexical/TF-IDF 权重不佳 |
| 改法 | ① **Query rewrite**（同义扩展：住宿→酒店/房费）；② 调整分块大小/重叠；③ 调 `RAG_LEXICAL_WEIGHT` / 向量权重（仅当评测证明需要） |
| 评测证明 | `hit` 类命中率↑；`must_hit_title_any` 原失败用例转 PASS；看 `retrieve_score` span |
| 勿做 | 一上来开大 embedding 模型掩盖分块问题 |

### 2.2 答案幻觉（空库或弱相关仍斩钉截铁）

| 项 | 内容 |
|----|------|
| 症状 | 无制度仍答「一般为 80%」；或引用了不相关文档却断言硬数字 |
| 根因假设 | 生成未绑定 hits；空结果分支未拦截；Prompt 未强制拒绝 |
| 改法 | ① **引用约束**（无 `document_id`/参考则拒答）；② **空结果强制拒绝**；③ `forbid_phrases` 回归；④ 弱相关阈值提高 |
| 评测证明 | `missing` 正确拒绝率↑；人工抽检幻觉条数↓ |
| 勿做 | 只加长 Prompt 不写评测 |

### 2.3 工具误调用（不该联网却联网 / 不该算却算）

| 项 | 内容 |
|----|------|
| 症状 | 问报销制度却走 `web_search`；或简单问答触发无用工具耗步数 |
| 根因假设 | 路由优先级过宽；空库自动 research；工具描述含糊 |
| 改法 | ① **收紧调用条件**（制度意图禁用自动 web，见 [02](02-完整链路设计.md)）；② 优化工具 description；③ 降低 `max_steps` 无效路径 |
| 评测证明 | `expected_intent` / `must_plan_step` 用例；Trace 中 `tool_web_search` 次数下降 |
| 勿做 | 关掉所有工具导致时间/计算全挂 |

### 2.4 多轮丢上下文

| 项 | 内容 |
|----|------|
| 症状 | 「那机票呢？」不再关联差旅；或指代「上面那个额度」失败 |
| 根因假设 | 每轮独立检索；未保留制度名/主题槽位 |
| 改法 | ① **历史摘要**（最近 N 轮压缩为主题）；② **槽位**：`policy_name`、`topic`；③ 追问改写为完整查询再检索 |
| 评测证明 | `multi_turn` 类用例；手工脚本串联两轮 |
| 勿做 | 把全文历史无截断塞进 Prompt 导致变慢且超窗 |

### 2.5 回答速度慢

| 项 | 内容 |
|----|------|
| 症状 | P95 `duration_ms` 过高；用户感知卡顿 |
| 根因假设 | LLM 超时偏长；串行工具；重复检索同一制度；无缓存 |
| 改法 | ① **高频制度问答缓存**（query hash → 答案，文档更新时失效）；② 工具并行（research+web 已有并行基础）；③ 制度 LOCAL 路径跳过无关工具；④ Mock/演示路径保持轻量 |
| 评测证明 | 同环境 P50/P95↓；`hit` 率不降 |
| 勿做 | 为了速度关掉引用校验 |

### 2.6 意图漂移 / 超范围硬答

| 项 | 内容 |
|----|------|
| 症状 | 闲聊或外司制度被当成内规回答 |
| 根因假设 | 缺少 OOS 门禁；检索噪声被当成依据 |
| 改法 | OOS 规则 + 低分拒绝；外司关键词拒答 |
| 评测证明 | `oos` 类 PASS 率↑ |

## 3. 优化选型优先级（建议）

```text
先做：空库拒绝 + 引用约束 + 制度禁自动 web     （反幻觉，评审敏感）
再做：query rewrite / 追问改写                 （抬 hit 率）
然后：多轮槽位摘要                             （体验）
最后：缓存 / 向量 / 图谱                       （性能与召回，需数据证明）
```

与开发流程对应：T2 → T4 → T5 → T6（见 [README.md](README.md)）。

## 5. 与 Trace 联查

优化前后对比同一 `query` 的 Trace：

- `intent` 是否变化  
- `retrieve_local` / `retrieve_score` 的 hits 与 backend  
- 是否出现多余 `tool_web_search`  
- `mode` 是否意外 `mock_fallback`  
- `duration_ms` 分段哪里变慢  

接口：`GET /api/runs`（详见 [05-工程化规范.md](05-工程化规范.md)）。
